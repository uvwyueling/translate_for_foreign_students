# Vercel 最小部署与连接验证

本次核实的官方文档说明：WebSocket Beta 可通过导出的 Node HTTP server 与 `ws` 建立连接，需要启用 Fluid compute；达到函数最大时长会断开，重连可能进入其他实例。

参考：[WebSockets](https://vercel.com/docs/functions/websockets)。这份文档只说明代码部署路径，不代表本项目部署验证已完成。

## 项目配置

1. 从本项目代码创建 Vercel 项目。框架选择 Vite，构建 `npm run build`，静态目录 `dist`，Node 版本使用兼容依赖的版本（建议 24）。
2. 保留 `api/server.ts` 与 `vercel.json`。API 路由转发到同一个 HTTP server，`/subtitles` 回退到网页入口。
   后端的相对导入必须使用编译后的 `.js` 后缀（如 `../server/app.js`）。项目采用 ESM，Node 不会自动补全文件扩展名。`tsconfig.server.json` 以 NodeNext 规则检查此限制；部署前运行 `npm run check`，其中会用普通 Node 加载编译后的入口并验证健康检查和模拟 WebSocket，不调用讯飞。
3. 确认项目开启 Fluid compute，并检查实际可用的 WebSocket Beta 与时长上限。配置请求的 `maxDuration` 是 300 秒；如套餐允许值更短，必须同步调低。`SESSION_MAX_SECONDS` 必须比平台上限至少短 30 秒，默认 240。
   `vercel.json` 明确指定 `regions: ["hkg1"]`，将转发函数放在香港，避免默认美国 `iad1` 与中国讯飞服务之间的长距离传输。配置位置依据[函数区域文档](https://vercel.com/docs/functions/configuring-functions/region)，区域代码见[区域列表](https://vercel.com/docs/regions)。这只是缩短网络路径的配置，不保证到讯飞的实际吞吐与稳定性；必须部署后验证。
4. 第一轮不配讯飞凭证，先验证模拟模式。后续配置真实凭证与课堂口令，重新部署；设置准确的 `ALLOWED_ORIGIN`。
5. 不在公开浏览器前端提供任何讯飞凭证；公开真实服务前设置足够长的随机课堂口令，教师保管。V0 采用共享口令，正式多用户访问控制留待后续版本。

不要把 `npm start` 搬到教室电脑。学校教师只需浏览器打开 HTTPS 应用地址。

## 500 FUNCTION_INVOCATION_FAILED 排查

先在项目 Logs 查看对应请求的具体异常。2026-10-18 首次线上部署日志为 `ERR_MODULE_NOT_FOUND: Cannot find module '/var/task/server/app' imported from /var/task/api/server.js`：编译后的入口保留了无扩展名的导入，Node 在模块加载时退出。缺少讯飞配置本应返回 `ok: true, liveConfigured: false`，不会造成这个模块加载错误。

本地已补全后端相对导入的 `.js` 后缀，增加 NodeNext 检查和编译产物启动测试。修复必须提交并推送到 GitHub，让 Vercel 重新部署；只重新部署旧提交不会包含修复。新部署 Ready 后重新打开 `/api/health`，期望 `ok: true`；真实模式还需要 `liveConfigured: true`。之后回首页刷新、重新检查麦克风，再验证模拟和真实连接。若仍有 500，查看新部署的最新日志，不能假定它与旧错误相同。

## 线上反复出现发送积压

2026-10-18，在更新启动缓存后的线上版本复现：`/api/health` 正常、WebSocket 返回 101、上游连接后返回 `ready`，但没有中文识别或英文字幕。连续模式发送 116 帧（4.64 秒）后返回 `UPSTREAM_BACKPRESSURE`；停顿模式发送 100 帧（4 秒）后返回 `SEGMENT_NETWORK_BACKLOG`。这里是客户端已经发送的音频时长，不表示讯飞已经收到。相同约 3.23 秒合成短句从本机直连讯飞，返回完整句子，无业务错误。

Vercel 请求日志显示实际函数运行在美国 `iad1`，连接在十余秒内结束，远早于配置的 300 秒平台时限。因此已定位的故障阶段是后端到讯飞的发送积压，不是健康接口、麦克风授权、字幕渲染或函数最长时限。尚未获得该次上游 TCP 的精确吞吐与丢包数据，不能断言地理区域是唯一原因。停顿模式已有发送节奏控制仍失败，说明只给连续模式限速不足以证明解决。

本地修复包括：

- 明确指定香港区域，部署后检查 `/api/health.runtimeRegion` 是否为 `hkg1`、`revision` 是否对应新提交。旧部署的健康接口没有这两个字段；只见 `ok: true` 不能确认修复已上线。
- 连续模式将网络集中到达的帧暂存并按 40 ms 节奏发送；两种模式遇到超过 64 KB 的短时写缓冲时等待恢复，保留原顺序，不立即丢掉整句。
- 不增加 64 KB 写缓冲阈值。暂存最多 150 帧 / 6 秒；持续阻塞 6 秒或暂存超限则停止并明确提示，避免持续失败的链路重复消耗会话。
- 运行排查信息和数字报告保留最后一次服务错误码；重试耗尽时不抹掉原始故障来源。健康接口只增加运行区域和提交短标识，不暴露密钥或课堂口令。

新部署验收必须通过真实线上短测：分别用连续和停顿模式发送同一固定合成短句，确认收到中文识别、最终中英字幕并保留句首与句尾；再做至少一分钟连续传输，检查积压和断连。未完成前不能视为线上已修复。若香港仍持续阻塞，应使用本次具体错误码和区域继续定位；需要评估独立常驻后端时再提出部署方案，不把失败归结成“所有 Vercel 都不支持 WebSocket”。

## 香港版本仍在连接阶段失败

已从线上健康接口确认提交 `e519aecda3e9`、运行区域 `hkg1`。真实短测返回 `PROVIDER_NETWORK`，没有 `ready`，发送音频帧数为 0，识别和翻译结果均为 0。用户观察到“正在连接 / 正在重连”循环，与该结果一致。切换香港尚未解决连接问题，不再把区域距离视为已证实的根因。

旧错误处理丢弃了底层 Error，只返回统一的 `PROVIDER_NETWORK`。本地补充安全的分阶段诊断，保持原有 8 秒握手超时和 TLS 校验：

- `PROVIDER_DNS_*`：域名解析未完成或明确返回解析错误。
- `PROVIDER_TCP_*`：DNS 已完成，TCP 尚未连接成功。
- `PROVIDER_TLS_*`：TCP 已连接，TLS 尚未完成；证书错误停止重试。
- `PROVIDER_UPGRADE_*`：TLS 已完成，WebSocket 握手尚未完成。
- `PROVIDER_OPEN_*`：WebSocket 已建立，之后连接出错。
- `PROVIDER_CONNECTION_*`：没有可用的阶段信息时保留为未细分连接错误，不猜测具体阶段。

“运行数据与排查”保留具体错误码。Vercel 日志中 `provider_connection_failed` 只含阶段、白名单错误码和耗时，不输出原始错误对象、鉴权 URL、请求头、密钥或课堂内容。诊断补丁需要部署后再复测；目前不能从统一错误码确定是 DNS、TCP、TLS、账号权限或供应商策略。

`ready` 当前只表示 WebSocket 已建立、可以开始上传，不证明讯飞业务已经返回成功。真实成功需要观察识别 / 翻译响应；讯飞协议也明确区分会话层状态与业务结果。控制台无用量记录与连接前失败相符，但不能单凭用量页证明所有历史调用状态，还需核对应用、查询时段及实际业务响应。本地直连的成功记录不能归为 Vercel 调用成功。
