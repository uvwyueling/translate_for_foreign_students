# 从本地验证到教师试讲

当前结论：本地真实链路可运行，用户本轮体验可接受；尚未部署，尚未完成课堂验收。本轮个人延迟计时结束，后续正式延迟由教师试讲评估。

## 1. 整理可部署版本

- 保存当前代码与配置说明，保留连续模式和停顿送译实验模式。
- 复核构建、自动化测试、依赖及内容保护：不上传 `.env`、服务凭证、运行录音或课堂字幕。
- 将代码放入 GitHub 私有仓库，保留锁文件与部署配置；当前目录尚未初始化 Git 仓库。
- 从该仓库创建 Vercel 项目，在后端环境变量中单独配置讯飞三项凭证与课堂口令，部署后记录应用地址。
- 核实部署环境的实时连接、实际函数时限与两段连接恢复，不能仅以首页可访问判断完成。

用户准备：可用的 GitHub 与 Vercel 账号、仓库归属、讯飞对应服务权限及测试额度。创建账号和付款升级不代替用户决定。

## 2. 尽早验证学校网络

拿到 HTTPS 地址后，由能到学校的同事使用教室电脑、无 VPN 打开。先确认网页、麦克风权限、双语字幕和英文声音可用，记录 Windows / Edge 版本。此时不要求教师登录 GitHub 或 Vercel 管理后台。

若无法访问，记录是网页、静态资源还是实时连接失败，再决定是否调整远程部署位置。

## 3. 核对教室设备与基本控制

按 [验收清单](ACCEPTANCE.md) 验证麦克风、两路投影、耳机线路、字幕可读性，以及暂停、继续、结束、清空待播与断线恢复。现场确认 25 个在用耳机的声音，不以电脑扬声器试听替代。

## 4. 教师先试讲 10–15 分钟

使用真实课程内容和实际讲课语速，重点记录漏译、术语错误、停顿分句、重复、播放积压及教师操作负担。正式延迟样本由教师试讲协助测量，区分起播时间与尾部跟随时间。

测试设置和模式要记录清楚。停顿送译在本地显著缩短短句等待，但真人停顿与教室噪声可能误分句，不能因本地满意就直接认定课堂适用。

## 5. 完成 45 分钟连续运行与时限交接

在实际部署环境覆盖真实服务、平台时限、主动断网恢复、课中与课末积压，以及用量。通过后再决定小范围课堂试用；问题记录保留给 V1。

本清单是准备顺序，不表示上述项目已经通过，也不要求用户继续手动做重复延迟计时。
